# DevBox 关键词矩阵

> 配套《技术方案.md》§6.5 内容架构使用。每个关键词对应一个落地页,直接驱动选题与开发排期。
> 日期:2026-07-01

---

## 选词标准与优先级

优先选(新站策略):

| 关键词类型 | 优势 | 本站落点 |
|-----------|------|---------|
| **低竞争长尾词** | 新站易排名 | 信息型内容页(示例/排查) |
| **高转化词** | 直接带来使用/转化 | 工具支柱页 |
| **问题型词**(是什么/怎么办) | 易进精选摘要 & AI 搜索回答 | 百科 / 排查页 |
| **对比型词**(A vs B) | 商业价值高、转化好 | 对比页 |

**上线顺序(先易后难,积累权重再打硬词):**

```
批次 P0:低竞争长尾词  ──►  批次 P1:中竞争专题词  ──►  批次 P2:高竞争核心词
(示例/问题/排查页)        (教程/生成器/工具页)        (品类词,靠站权重顶上去)
```

**字段说明**
- **类型**:长尾 / 专题 / 核心 / 对比
- **意图**:信息(是什么/怎么做/排查)/ 交易(用工具)/ 对比
- **竞争**:低 / 中 / 高(经验判断,**上线前用关键词工具复核**)
- **落地页**:该词主打的页面(pillar=工具支柱页;其余为内容页)
- **批次**:P0 先做 → P1 → P2

## 5. 如何用这张矩阵

1. **一词一落地页**:同一落地页可承接多个同簇长尾(如 `/cron/examples` 用不同 H2 覆盖"每5分钟""每天凌晨""每周一"),避免为每个近义词单开页面导致自相竞争(关键词蚕食)。
2. **开发排期 = 批次顺序**:先把所有工具的 **P0 长尾内容页**铺满(新站最快见效),再回头补 P1 专题/工具页打磨,P2 核心词随站权重自然上升,不硬冲。
3. **落地页与内容架构对齐**:`examples` / `guide` / `what-is-x` / `troubleshooting` / `vs-x` 全部是《技术方案.md》§6.5 定义的内容类型,frontmatter 的 `type` 字段直接对应。
4. **上线前复核数据**:用关键词工具核对每个词的真实搜索量/竞争度,砍掉 0 搜索量的、合并重复的;发现新长尾随时补进矩阵(矩阵是活文档)。
5. **每篇内容锁定 1 主词 + 2–4 副词**:主词进 H1/title/首段,副词进 H2/正文,自然覆盖,不堆砌。
