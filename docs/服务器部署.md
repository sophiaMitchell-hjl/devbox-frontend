## 0. 架构与关键路径

| 项 | 值 |
|------|------|
| 前端 | Astro 静态站,构建产物 `web/dist/` |
| 后端 | FastAPI(仅 `/api` 只读接口,如 IP 查询),容器跑在服务器 `127.0.0.1:8001` |
| 服务器 | Debian,SSH 登录 `root@45.202.241.233` |
| 仓库目录(服务器) | `/root/devbox` |
| 网站根目录(nginx `root`) | `/var/www/devbox` |
| nginx 配置 | `/etc/nginx/conf.d/devbox.conf` |
| 域名 / CDN | `devbox.nextlink.me`,走 Cloudflare |
| GitHub 仓库 | `git@github.com:sophiaMitchell-hjl/devbox-frontend.git` |

部署链路:`本地 push → GitHub → 服务器 git pull → 构建 → rsync 到 /var/www/devbox → Cloudflare 边缘缓存`。

## 1. 首次配置:SSH 免密拉代码(Deploy Key)

> 目的:服务器 `git pull` 不再每次输 GitHub token。用**只读部署密钥**,泄露也只能读这一个仓库,可随时在 GitHub 吊销。
> 以下命令都在**服务器上**执行(SSH 登录后)。

### 1.1 生成专用密钥
```bash
mkdir -p ~/.ssh && chmod 700 ~/.ssh
ssh-keygen -t ed25519 -C "devbox-server" -f ~/.ssh/devbox_deploy -N ""
cat ~/.ssh/devbox_deploy.pub          # 复制这一整行(ssh-ed25519 ... devbox-server)
```
`-N ""` = 不设密码,自动部署才不会卡在密码提示。

### 1.2 把公钥加到 GitHub
仓库 → **Settings → Deploy keys → Add deploy key** → 粘贴公钥 → **不要勾** "Allow write access"(只拉取)→ 保存。
链接:https://github.com/sophiaMitchell-hjl/devbox-frontend/settings/keys

### 1.3 让 SSH 用这把钥匙连 GitHub
```bash
cat >> ~/.ssh/config <<'EOF'

Host github.com
  IdentityFile ~/.ssh/devbox_deploy
  IdentitiesOnly yes
EOF
chmod 600 ~/.ssh/config ~/.ssh/devbox_deploy
```

### 1.4 仓库地址切成 SSH 并验证
```bash
cd /root/devbox
git remote set-url origin git@github.com:sophiaMitchell-hjl/devbox-frontend.git
ssh -T git@github.com      # 首次问 yes/no → 输 yes
git pull --ff-only         # 不再要 token 即成功
```
`ssh -T` 成功标志:`Hi sophiaMitchell-hjl/devbox-frontend! You've successfully authenticated, but GitHub does not provide shell access.`(后半句是正常的,不是报错。)

> 用 Termius 连服务器时,以上步骤完全一样,只是把 SSH 终端换成 Termius 的终端。Termius 自带的「Keys」是给「设备→服务器」用的,与本节的「服务器→GitHub」密钥无关,别混淆。

## 2. 日常部署

代码改动 push 到 `master` 后,在服务器执行:
```bash
cd /root/devbox && bash deploy.sh
```

`deploy.sh` 做的事(`set -euo pipefail`,任一步失败即停,不会跑到 rsync 误删):
1. `git pull --ff-only` —— 拉最新代码
2. `cd web && npm install && npm run build` —— 构建(含内链校验,死链会拦下)
3. `rsync -a --delete dist/ /var/www/devbox/` —— 同步到网站根(`--delete` 清理旧文件)
4. 清 Cloudflare 缓存(需先设环境变量,见下)

### 2.1 让 deploy.sh 自动清 Cloudflare 缓存(可选)
```bash
export CF_ZONE_ID=xxxxx
export CF_API_TOKEN=xxxxx      # 权限:Zone → Cache Purge
```
未设则跳过,需到 Cloudflare 后台手动 **Purge Everything**。

### 2.2 构建工具前置
服务器需有 `node`、`npm`、`rsync`。当前环境:Node v20(经 nvm)、npm 10、rsync 3.2。校验:
```bash
node -v; npm -v; rsync --version | head -1
```
若 `node/npm: command not found`(非交互 shell 未加载 nvm),在 `deploy.sh` 顶部或 `~/.bashrc` 里 source nvm:
```bash
export NVM_DIR="$HOME/.nvm"; [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh"
```

## 3. Cloudflare 排查

### 3.1 robots.txt 被 Cloudflare 改写(AI 爬虫被屏蔽)

**现象**:线上 `curl -s https://devbox.nextlink.me/robots.txt` 出现一大段 `Content-Signal:` 注释,以及 `User-agent: GPTBot / ClaudeBot / Google-Extended … Disallow: /`,而不是仓库里 `web/public/robots.txt` 那份。

**原因**:Cloudflare 两个 AI 功能在**边缘层**注入(与服务器无关,服务器不用动):

| 注入内容 | 功能 | 关闭位置 |
|---|---|---|
| `User-agent: GPTBot… Disallow: /` | **Managed robots.txt** | Security → Bots / **AI Crawl Control** → robots.txt 开关 → 关 |
| `Content-Signal: …` + 顶部注释 | **Content Signals Policy** | 域名 **Overview → Control AI Crawlers** → 取消勾选 **Display Content Signals Policy**(免费套餐也可在 Security → Settings) |

**影响**:被屏蔽的是 AI 用途(ChatGPT/Claude/Perplexity/Google AI 概览引用),**不影响普通 Google 搜索收录**(`Googlebot` 未被屏蔽,`Google-Extended` 才是 AI 用途)。想要 AI 搜索曝光就两个都关。

**处理**:两个开关都关 → **Caching → Purge Everything** 清缓存 → 等 1–2 分钟。
期望结果只剩:
```
User-agent: *
Allow: /
Disallow: /api

Sitemap: https://devbox.nextlink.me/sitemap-index.xml
```

> 注:这份 robots.txt 由 Cloudflare 边缘生成,加 `?t=时间戳` 绕不掉缓存;必须在 CF 后台清缓存或关功能。

参考:
- https://developers.cloudflare.com/bots/additional-configurations/managed-robots-txt/
- https://blog.cloudflare.com/content-signals-policy/

### 3.2 改了内容但线上没变
Cloudflare 缓存了 HTML/静态资源。**Caching → Configuration → Purge Everything**,或用 3.1 里的 `deploy.sh` 自动清缓存。

## 4. 快速自检命令(本地或任意联网机器)

```bash
# 页面是否含 og:image
curl -s https://devbox.nextlink.me/ | grep -o '<meta property="og:image[^>]*>'

# OG 图是否在线(应 200 + image/png)
curl -sI https://devbox.nextlink.me/og-default.png | grep -iE 'HTTP/|content-type'

# sitemap 是否可访问 + URL 数
curl -sI https://devbox.nextlink.me/sitemap-index.xml | grep -i 'HTTP/'
curl -s  https://devbox.nextlink.me/sitemap-0.xml | grep -o '<loc>' | wc -l

# robots.txt 是否干净(不应再有 GPTBot / Content-Signal)
curl -s https://devbox.nextlink.me/robots.txt
```

## 5. 常见问题速查

| 现象 | 原因 / 解决 |
|---|---|
| `ssh -T` 报 `Permission denied (publickey)` | 公钥没加成功或加错仓库,回 §1.2 核对 |
| `Bad owner or permissions on ~/.ssh/config` | `chmod 600 ~/.ssh/config ~/.ssh/devbox_deploy; chmod 700 ~/.ssh` |
| `git pull` 仍要密码 | remote 没换成功,`git remote -v` 看是否还是 `https://`,重做 §1.4 |
| `bash: deploy.sh: No such file` | 文件没在服务器,`git pull` 拉取(deploy.sh 已在仓库根) |
| 构建 `node/npm: command not found` | nvm 未加载,见 §2.2 |
| robots.txt 还带 AI 屏蔽 | Cloudflare 两个开关只关了一个,见 §3.1 |
| OG 图 404 | `web/public/og-default.png` 没提交/推送,或未重新构建部署 |
