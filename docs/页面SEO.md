# DevBox 页面 SEO 优化

> 每个页面对应**一个明确搜索意图**(对齐《关键词矩阵.md》)。本文档承接页面级 on-page 优化,逐步补齐 Title / Description / H1 / 正文 / 图片等。
> 日期:2026-07-01

---

## 1. Title 标题

### 公式

```
核心关键词  +  用户收益  +  时间/场景/版本(可选)  +  | 品牌
```

- **核心关键词靠左**:该页在《关键词矩阵》里锁定的**主词**放最前(搜索引擎与用户都左向加权)。
- **一页一意图一主词**:Title 只服务这一个意图,不塞多个不相关词。
- **品牌后缀** ` | DevBox`:除首页(品牌本身即核心词)外统一带上,建品牌记忆。
- **问题型页用问句**:百科/排查页用"…是什么?""…怎么办?",契合问题型词,利于抢**精选摘要 / AI 搜索回答**。

### 各页型 Title 模板与实例

| 页面 | Title 模板 | 实例(cron 集群) | 目标主词 |
|------|-----------|-----------------|---------|
| 首页 | `{品牌} - {一句话定位}:{品类列举}` | DevBox - 开发者在线工具箱:配置生成 / 正则 / Cron / 命令构建 | 品牌 + 品类 |
| 分类页 | `{分类}工具 - {子工具列举}在线生成 \| DevBox` | 配置生成工具 - Nginx / Docker / Cron 在线生成 \| DevBox | 配置生成工具 |
| 工具支柱页 | `{工具}生成器 - {核心收益} \| DevBox` | Cron 表达式生成器 - 在线可视化生成、解释与执行预览 \| DevBox | cron 表达式生成器 |
| 百科 | `{工具}是什么?{补充卖点} \| DevBox` | Cron 是什么?crontab 表达式格式详解 \| DevBox | cron 是什么 |
| 教程 | `{工具}怎么写?{收益/范围} \| DevBox` | Cron 表达式怎么写?5 个字段规则详解与示例 \| DevBox | cron 表达式怎么写 |
| 示例集 | `{工具}示例大全:{高频场景列举} \| DevBox` | Cron 表达式示例大全:每5分钟 / 每天 / 每周怎么写 \| DevBox | cron 示例 |
| 排查 | `{问题}怎么办?{解决法} \| DevBox` | crontab 不执行怎么办?排查步骤与解决方法 \| DevBox | crontab 不执行 |
| 对比 | `{A} vs {B}:{决策收益} \| DevBox` | Cron vs systemd timer:区别对比与如何选择 \| DevBox | cron vs systemd timer |
| 博客 | `{标题问法} \| DevBox` | 自建 VPN 完整指南:从选型到部署 \| DevBox | (按文定) |

> 其余工具(regex/nginx/docker-compose)套同模板。例:`Nginx 反向代理配置生成器 - 一键生成并切换 Caddy | DevBox`、`nginx 502 bad gateway 怎么办?原因与解决方法 | DevBox`。

### 写作规则

- **长度**:中文控制在 **~30 字以内**(Google 约 600px / ~28–32 汉字截断),核心词务必落在前 20 字,避免被截断丢失。
- **唯一性**:全站 **Title 不重复**(重复 Title 会自相竞争、被判低质),由模板 + 工具名保证天然唯一。
- **真实相符**:Title 必须与页面内容一致,不夸大、不诱导点击(clickbait),不承诺页面没有的东西。
- **Title 与 H1 可不同**:Title 面向 SERP 点击率(可含品牌、问句);H1 面向页面主题(更简洁)。二者主词一致即可,不必逐字相同。

### 关于"时间/版本"(分情况用,别一刀切)

| 页面类型 | 加年份/"最新"? | 原因 |
|---------|--------------|------|
| 工具支柱页 | **不加** | 常青内容,加"2026"制造每年维护负担、过期显旧,反伤 CTR |
| 教程 / 排查 / 博客 | **可加** | 传递新鲜度、利于点击;但**加了就要每年更新正文并同步年份**,否则不如不加 |
| 版本强相关页 | 加版本号 | 如某工具语法随大版本变时,标明版本更精准 |

> 原则:年份/版本**只在真能反映新鲜度且你愿意维护时**才加;工具页保持常青。

### 反面(本站禁止)

关键词堆砌 —— 可能被判操纵排名(见下方 Spam 政策):
```
Cron_Cron表达式_Cron生成_Cron在线_Cron解释_Cron工具_crontab      ✗
SEO教程_SEO优化_SEO排名_SEO关键词_SEO外链                          ✗
```
以及:与内容不符的 Title、纯为点击的标题党、每页复制同一 Title。

### 合规(Google Spam Policies)

参考 https://developers.google.com/search/docs/essentials/spam-policies

- **禁关键词堆砌**(keyword stuffing):Title/正文不重复堆同义词。
- **禁误导**:Title 与页面实际内容/意图相符,不做诱导。
- **禁 doorway/门页**:不为单个近义词批量生成雷同薄页(对应《网站结构》一词一落地页原则)。
- 面向用户写,不为操纵排名而写。

### 实现

`lib/seo.ts` 按页型模板 + 工具注册表自动产出 Title,页面不手写:

```ts
// lib/seo.ts
export function toolTitle(t: Tool)      { return `${t.title} - ${t.benefit} | DevBox`; }
export function articleTitle(a: Article){ return `${a.seoTitle} | DevBox`; }  // seoTitle 来自内容 frontmatter
// 校验:构建期断言 title 唯一 & 长度 ≤ 上限,超限告警
```

内容页的 `seoTitle` 写在文章 frontmatter(作者按模板填最优问法),工具页从注册表的 `title`+`benefit` 拼装。构建期做**唯一性 + 长度**校验,不达标直接报错,防止上线劣质 Title。

## 2. Meta Description(描述)

Description **不是直接排名因素**,但影响:**搜索结果点击率(CTR)、用户预期、主题理解、品牌表达**。留空则 Google 自抓正文片段(往往不理想),所以每页主动写。

### 结构

```
说明页面内容  +  解决的问题  +  适合人群  +  页面价值(差异点/CTA)
```

### 各页型实例(四要素齐全)

| 页面 | Meta Description 实例 |
|------|----------------------|
| 首页 | DevBox 开发者在线工具箱:Nginx/Caddy 配置、Docker Compose、Cron 表达式、正则调试等,填参数即出配置与命令,复制可用,纯浏览器计算、免注册。 |
| 分类页 | 配置生成工具集:Nginx 反代、Docker Compose、Cron 等常用配置在线填表即生成,复制即用、免安装,面向开发者与运维。 |
| 工具页 | 在线 Cron 表达式生成器:可视化选择即生成 crontab,自动人话解释并预览未来执行时间。开发者/运维不用背语法,填表单直接复制,免费纯前端。 |
| 百科 | Cron 是什么?讲清 crontab 五个字段的含义与格式,配示例与常见误区,面向刚接触定时任务的开发者,读完即会看懂并写出 cron 表达式。 |
| 教程 | 手把手教 cron 表达式怎么写:五字段与 `* / , -` 用法,配每5分钟/每天/每周实例。新手也能写出正确 crontab,并用在线工具即时校验。 |
| 示例集 | cron 表达式示例大全:每5分钟、每小时、每天凌晨、每周一等高频场景写法,复制即用,附在线生成器随改随验。 |
| 排查 | crontab 不执行怎么办?汇总环境变量、PATH、权限、日志等常见原因与排查步骤,帮你快速定位 cron 不生效问题并修复。 |
| 对比 | Cron 和 systemd timer 怎么选?从语法、精度、日志、依赖等维度对比优缺点与适用场景,帮你为定时任务选对工具。 |

### 规则

- **长度 ~80 汉字内**(移动端约 ~78 字截断),**关键信息前置**,避免价值点被截掉。
- **含主词但自然通顺**:主词会在 SERP 里加粗,但不堆砌、不重复。
- **每页唯一**:不复制同一段描述到多页。
- **带差异点/轻 CTA**:如"复制即用""免注册""纯浏览器",提升点击。
- **与内容相符**:不夸大、不承诺页面没有的内容(同 Spam 政策)。

### 实现

- 工具页:从注册表 `desc` 生成;内容页:写在 frontmatter `description`。
- `lib/seo.ts` 统一注入 `<meta name="description">` 与 `og:description`;构建期校验**唯一性 + 长度**,超限告警。

## 3. H 标签结构

标题层级传达**内容逻辑**,不是字号工具。

### 基本原则

- **每页仅一个 `<h1>`**,含该页核心词,与 Title 主词一致(文案可略简)。
- **`<h2>` = 大章节,`<h3>` = 小节**;**不跳级**(不出现 h2 直接跳 h4)。
- 层级**符合内容逻辑**,不为视觉大小乱用标签(字号交给 CSS)。
- **H2 自然嵌同簇长尾词**(对齐《关键词矩阵》),但读起来是自然小标题,非关键词列表。
- **FAQ 区**:`<h2>常见问题</h2>` 下每个问题用 `<h3>`,并注入 `FAQPage` 结构化数据。

### 各页型 Hn 大纲

**工具支柱页 `/cron`**
```
h1  Cron 表达式生成器
h2  在线生成(工具交互区)
h2  Cron 表达式怎么用
h2  常见 Cron 表达式示例
    h3  每 5 分钟执行
    h3  每天凌晨执行
h2  常见问题
h2  相关工具
```

**教程 `/cron/guide`**
```
h1  Cron 表达式怎么写
h2  Cron 的五个字段
    h3  分钟 / 小时 / 日 / 月 / 周
h2  特殊字符含义(* , - /)
h2  常见写法示例
h2  用在线工具校验
h2  常见问题
```

**示例集 `/cron/examples`**(每个高频长尾 = 一个 H2)
```
h1  Cron 表达式示例大全
h2  每 5 分钟执行一次
h2  每小时执行
h2  每天凌晨执行
h2  每周一执行
h2  每月 1 号执行
```

**排查 `/cron/troubleshooting`**
```
h1  crontab 不执行怎么办
h2  确认 cron 服务在运行
h2  检查环境变量与 PATH
h2  检查权限与执行用户
h2  查看 cron 日志定位
h2  常见问题
```

**对比 `/cron/vs-systemd-timer`**
```
h1  Cron vs systemd timer:怎么选
h2  语法与配置对比
h2  精度与功能差异
h2  日志与调试
h2  如何选择(场景建议)
h2  常见问题
```

> 其余工具套同骨架。工具页的 Hn 由 `ToolLayout` 固定产出;内容页的 Hn 由 Markdown 标题层级生成——**写作规范要求作者从 H2 起、不跳级**,构建期可加校验(检测 h1 数量=1、无跳级)。
