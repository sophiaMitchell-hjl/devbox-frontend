## 1. 通用模板 → DevBox 的映射

SEO 教程给的是「软件下载站」通用模板,本站是「在线工具集站」,做如下适配(不照搬):

| 通用模板 | DevBox 对应 | 说明 |
|---------|------------|------|
| 首页 | 首页 `/` | 工具总列表 + 分类入口 |
| 分类页 / 子分类页 | 分类页 `/category/<cat>` | 按 config/text/cli 归类工具 |
| 内容页 | 信息型内容页 | 百科/教程/示例/排查(挂在各工具下) |
| **产品页 / 软件页** | **工具支柱页 `/<tool>`** | 工具本体即"产品",交易型词落点 |
| **下载页** | **❌ 无** | 在线工具,无下载;工具页即完成使用 |
| 专题页(教程/对比/FAQ 集合) | 集合 hub 页 `/guides` `/compare` `/faq` | 跨工具聚合,内容仍在各工具 silo 下 |
| 博客页 | `/blog` | 不绑定具体工具的泛信息型内容 |
| 关于/联系/隐私/条款 | `/about` `/contact` `/privacy` `/terms` | 信任页,E-E-A-T 必备 |

> **关键差异**:没有"下载页";"产品页"=可交互的工具本体。这是工具站与下载站的本质区别。

## 2. 完整站点树

```
/                                   首页(工具卡片列表 + 分类导航 + 站内搜索)
│
├── /category/config                分类页 · 配置生成(nginx, docker-compose, clash…)
├── /category/text                  分类页 · 文本处理(regex…)
├── /category/cli                   分类页 · 命令构建(curl, git…)
│
├── /cron                       ★  工具支柱页(产品页,交易型)
│   ├── /cron/what-is-cron          百科  · 信息·是什么
│   ├── /cron/guide                 教程  · 信息·怎么做
│   ├── /cron/examples              示例集 · 信息·怎么做(长尾聚合)
│   ├── /cron/troubleshooting       排查  · 信息·排查
│   └── /cron/vs-systemd-timer      对比  · 商业型
├── /regex          … 同结构(what-is-regex / guide / examples / troubleshooting)
├── /nginx          … 同结构(… / vs-caddy)
├── /docker-compose … 同结构(… / vs-docker-run)
│
├── /guides                         专题 · 教程集合(hub,聚合各 silo 的 guide/examples)
├── /compare                        专题 · 对比集合(hub,聚合各 silo 的 vs 页)
├── /faq                            专题 · FAQ 集合(hub)
│
├── /blog                           博客(泛信息型,不绑定单个工具)
│   └── /blog/<slug>
│
├── /about                          关于我们(作者/维护者,建 E-E-A-T)
├── /contact                        联系方式
├── /privacy                        隐私政策
└── /terms                          服务条款
```

**层级控制**:任何页面距首页 ≤ 3 次点击。首页 → 工具页(1)→ 内容页(2)。集合 hub 与分类页提供第二条抓取路径,缩短深页距离。

## 3. URL 架构决策(核心,须先拍死)

两套互斥方案:

**方案 A · 按工具 silo 嵌套(推荐)**
```
/cron                       /cron/guide      /cron/vs-systemd-timer
```
- ✅ 主题集群 URL 上即成"筒仓(silo)",同簇内容路径相邻,权重高度聚合
- ✅ 面包屑天然:首页 › Cron › 教程
- ✅ 内链筒仓清晰,契合本站"每工具一集群"的核心打法
- ✅ 用户从 URL 一眼看出隶属关系

**方案 B · 按内容类型前缀(教程模板的写法)**
```
/tools/cron   /blog/cron-guide   /compare/cron-vs-systemd-timer   /faq/crontab-not-running
```
- ✅ `/blog` `/compare` 各自形成类型级板块权威
- ❌ 同一工具的内容被打散到不同路径,集群被切碎
- ❌ 面包屑与筒仓弱

**推荐 A**,并用**集合 hub 页兼得 B 的好处**:内容 canonical URL 走 A 的嵌套路径;`/guides` `/compare` `/faq` 作为聚合页去**链接**(而非占有)这些 URL。这样既有紧凑筒仓,又有类型级专题入口。

> URL 一旦上线被索引就应**稳定不改**(改动需 301,损耗权重)。所以此决策必须开工前定死 —— 见文末确认项。

**工具页放根 `/cron` 还是 `/tools/cron`?**
- `/cron`:更短(URL 规则要求简短)、工具即品牌主体;需维护保留字清单避免与 `/about` 等冲突。
- `/tools/cron`:命名空间清晰、零冲突、更稳妥。
- 倾向 **`/cron`**(简短优先,工具是主角),保留字清单在 `lib/tools.ts` 统一管控。

## 4. URL 设计规则(遵循教程,落到本站)

满足:**简短 / 稳定 / 可读 / 含主题义 / 无意义参数 / 不频繁改**。

本站 URL 规范表:

| 页面类型 | URL 模式 | 示例 |
|---------|---------|------|
| 首页 | `/` | `/` |
| 分类页 | `/category/<cat>` | `/category/config` |
| 工具支柱页 | `/<tool>` | `/cron` |
| 百科 | `/<tool>/what-is-<tool>` | `/cron/what-is-cron` |
| 教程 | `/<tool>/guide` | `/nginx/guide` |
| 示例集 | `/<tool>/examples` | `/cron/examples` |
| 排查 | `/<tool>/troubleshooting` | `/nginx/troubleshooting` |
| 对比 | `/<tool>/vs-<other>` | `/nginx/vs-caddy` |
| 教程集合 | `/guides` | `/guides` |
| 对比集合 | `/compare` | `/compare` |
| FAQ 集合 | `/faq` | `/faq` |
| 博客文章 | `/blog/<slug>` | `/blog/self-host-vpn-guide` |
| 信任页 | `/about` `/contact` `/privacy` `/terms` | — |

约定:
- **全小写 + 连字符 `-`**,不用下划线、不用空格、不用中文(避免 `%E4%B8...` 转义)。
- **slug 英文、语义化**;中文 SEO 靠 H1/title/正文,不靠 URL。
- **无 `.html`/`.php` 后缀、无查询参数**(Astro 静态输出天然满足)。
- **尾斜杠统一**(Astro `trailingSlash` 配置固定一种,另一种 301 到它,避免重复 URL)。
- **稳定**:slug 定了就不改;若必须改,旧 URL 保留 301。

反例(本站禁止):
```
/index.php?id=123&cat=88          ← 参数、无语义
/page/2026/06/07/a1b2c3.html      ← 日期路径 + 乱码 + 后缀
/nginx-config-best-free-2026.html ← 关键词堆砌
```

## 5. 权重传递与内链筒仓

- **首页**权重最高 → 链向所有工具支柱页(一级)与分类页。
- **工具支柱页**(集群枢纽)→ 链向本簇全部内容页;内容页 → 反链回支柱页(CTA)+ 互链同簇兄弟页。形成闭合筒仓,权重内聚。
- **集合 hub**(`/guides`/`/compare`/`/faq`)→ 横向聚合跨工具同类型页,给深页第二条抓取路径。
- **面包屑**每页都有(注入 `BreadcrumbList` JSON-LD),强化层级信号。
- **相关工具**互链(cron ↔ 其他配置工具),扩大簇间连接。
- 内链全部由 `lib/tools.ts` + 内容集合数据**自动生成**,避免手工维护出现孤儿页(orphan page)。

## 6. 抓取与索引配置

- **`sitemap.xml`**:`@astrojs/sitemap` 自动生成,含全部工具页 + 内容页 + hub。
- **`robots.txt`**:放行全站,指向 sitemap;屏蔽无 SEO 价值路径(如未来的 `/api`)。
- **canonical**:每页自指 canonical;集合 hub 只做聚合、不与内容页争 canonical。
- **结构化数据**:首页 `WebSite`+`SearchAction`;工具页 `SoftwareApplication`+`FAQPage`;教程 `HowTo`;百科 `Article`;每页 `BreadcrumbList`。
- **404 / 500**:自定义页,404 引导回首页/热门工具。

## 7. 面包屑导航

面包屑同时服务四个目的:用户定位、搜索引擎理解层级、改善站内导航、增强结构化数据展示(Google 可在结果里显示面包屑路径替代裸 URL)。

### 各页型的面包屑路径

**面包屑最多 3 级**,与 URL 深度一致。不插入"分类"层级(避免内容页变成 4 级);分类仅作首页筛选与分类页存在,不进面包屑:

| 页面 | 面包屑 | 级数 |
|------|--------|------|
| 首页 | (不显示,或仅 `首页`) | — |
| 分类页 | 首页 › 配置生成 | 2 |
| 工具支柱页 | 首页 › Cron 生成器 | 2 |
| 教程 | 首页 › Cron 生成器 › 使用教程 | 3 |
| 示例集 | 首页 › Cron 生成器 › 示例大全 | 3 |
| 百科 | 首页 › Cron 生成器 › Cron 是什么 | 3 |
| 排查 | 首页 › Cron 生成器 › 问题排查 | 3 |
| 对比 | 首页 › Cron 生成器 › Cron vs systemd timer | 3 |
| 集合 hub | 首页 › 教程集合 | 2 |
| 博客文章 | 首页 › 博客 › {文章标题} | 3 |
| 信任页 | 首页 › 关于我们 | 2 |

> 全站封顶 3 级。若日后出现子分类,合并展示或用"…"折叠中间级,末级始终是当前页——不突破 3 级。

内容类型 → 面包屑末级中文标签(集中管理,勿散落):

```ts
// lib/breadcrumb.ts
export const TYPE_LABEL: Record<string, string> = {
  guide: '使用教程',
  examples: '示例大全',
  wiki: 'XX 是什么',      // 运行时替换 XX 为工具名
  troubleshooting: '问题排查',
  compare: '对比',        // 实际用 `${tool} vs ${other}`
};
```

### 设计规则

- **最多 3 级**:首页 › 工具 › 内容页;工具页与分类页 2 级。不加分类中间层。
- **末项 = 当前页,不作链接**(纯文本 + `aria-current="page"`);其余项均为可点真实页面。
- **层级 = URL 深度**:`/cron/guide` → 首页 / Cron 生成器 / 使用教程,一一对应,直观且稳定。
- **文案简洁**:用工具短名(`Cron 生成器`)而非全 title,避免过长。

### 结构化数据(BreadcrumbList JSON-LD)

每页可见面包屑之外,注入 `BreadcrumbList`。示例(`/cron/guide`):

```json
{
  "@context": "https://schema.org",
  "@type": "BreadcrumbList",
  "itemListElement": [
    { "@type": "ListItem", "position": 1, "name": "首页",        "item": "https://devbox.tools/" },
    { "@type": "ListItem", "position": 2, "name": "Cron 生成器",  "item": "https://devbox.tools/cron" },
    { "@type": "ListItem", "position": 3, "name": "使用教程" }
  ]
}
```
> 末项省略 `item`(当前页)符合规范;每项 `item` 必须是真实可访问 URL。

### 组件实现

- **`Breadcrumb.astro`**:入参 `items: {name, href?}[]`;渲染 `<nav aria-label="面包屑">` + 有序列表 + 同源 JSON-LD `<script type="application/ld+json">`。可见 DOM 与 JSON-LD 由同一份数据生成,保证一致(Google 政策要求结构化数据须与页面可见内容一致)。
- **`lib/breadcrumb.ts`**:`buildTrail(tool, pageType, extra?)` 从工具注册表拼出 `items` 数组;`ToolLayout`/文章布局自动调用,页面无需手写面包屑,杜绝不一致与孤儿层级。
- **可访问性**:`<nav aria-label>`、`aria-current="page"`、分隔符 `›` 用 CSS `::before` 而非文本(读屏不念分隔符)。

### 合规要点(Google 结构化数据政策)

参考 https://developers.google.com/search/docs/appearance/structured-data/sd-policies

- 面包屑必须**反映页面在站内的真实位置**,不得伪造层级或堆关键词。
- 结构化数据须**与用户可见内容一致**(所以 JSON-LD 与可见面包屑同源生成)。
- 所有 `item` 链接指向**真实存在、可抓取**的页面,不得指向 404 或屏蔽页。
- 不得用面包屑做与导航无关的营销/垃圾信息。
- 上线后用 **Google 富媒体结果测试 / Search Console** 校验无报错。
